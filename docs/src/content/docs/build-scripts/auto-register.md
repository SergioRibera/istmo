Rust-side auto-wiring picks up plugin **clients** transparently through
`istmo::runtime!` (see [Auto-wiring](/advanced/auto-wiring/)). The
native side needs its own mechanism because the plugin **backends** —
`<T>BackendImpl.kt` / `<T>BackendImpl.swift` — are user-authored code
that only the app knows how to construct.

`istmo-build` closes the gap by emitting a **`IstmoPluginRegistry`**
file into your app. Call `registerAll(...)` once and every eligible
plugin's dispatcher is wired to the runtime.

## The generated file

For an app whose Android package resolves to `com.myapp.gen`,
`istmo-build` writes:

```kotlin
// android/app/src/main/java/com/myapp/gen/IstmoPluginRegistry.kt
// GENERATED by istmo-build - DO NOT EDIT.

package com.myapp.gen

import android.content.Context
import dev.istmo.runtime.IstmoRuntime

object IstmoPluginRegistry {
    fun registerAll(context: Context, runtime: IstmoRuntime = IstmoRuntime.instance) {
        runtime.registerHandler(
            DataStoreDispatcher.PLUGIN_ID,
            DataStoreDispatcher(
                DataStoreFactoryImpl(context),
                DataStoreCodecsImpl(),
            ),
        )
        // …one block per auto-registerable plugin
    }
}
```

The iOS mirror lives at `ios/<AppDir>/Plugins/IstmoPluginRegistry.swift`
with a matching `enum IstmoPluginRegistry.registerAll(...)`.

## Call it

Wire the registry into your `Activity.onCreate` (Android) or `App.init`
(iOS) alongside runtime start-up:

```kotlin
// Android
override fun onCreate(savedInstanceState: Bundle?) {
    IstmoRuntime.instance.start(this)
    IstmoPluginRegistry.registerAll(applicationContext)
    super.onCreate(savedInstanceState)
}
```

```swift
// iOS
@main
struct MyApp: App {
    init() {
        IstmoRuntime.shared.start()
        IstmoPluginRegistry.registerAll()
    }
    var body: some Scene { ... }
}
```

That's the entire wire-up. No per-plugin `registerHandler` calls.

## What "eligible" means

A plugin appears in the registry when **all** of these hold:

- The plugin's role is `host` (the native side implements the backend).
  `client` role plugins do not register a dispatcher — they generate a
  `<T>Client` for the native side to call.
- The plugin's `istmo.toml` has `auto_register = true` (default).
- The app's `istmo.toml` does not override with `auto_register = false`
  for that plugin.
- The app-level `[app] auto_register` is not `false`.

Everything else falls through to manual registration.

## Construction convention

The registry constructs the dispatcher assuming a fixed convention:

- **Stateless plugins**: `<T>Dispatcher(<T>BackendImpl(...), <T>CodecsImpl())`.
- **Stateful plugins** (trait declared with `init = Config`):
  `<T>Dispatcher(<T>FactoryImpl(...), <T>CodecsImpl())` — the factory
  materialises a backend per instance.

Argument passed to the backend/factory constructor:

- **Android**: `context: Context` (the `applicationContext` you passed
  to `registerAll`).
- **iOS**: no arguments — Swift constructors that need extra config
  reach for `IstmoRuntime.shared` or app-level singletons.

If your plugin's `BackendImpl`/`FactoryImpl` needs anything else,
opt out and register manually.

## Opting out

### Per plugin (plugin author)

Declare the plugin as not auto-registerable in its own `istmo.toml`:

```toml
[plugin]
id            = "acme.push_notifications"
client_type   = "::acme_push::PushClient"
auto_register = false
```

This is the right choice when the backend has a bespoke constructor
that varies across apps (e.g. requires an API key at construction time,
or a shared `HttpClient`).

### Per plugin (app author)

Override in the app's `istmo.toml`:

```toml
[[app.plugin]]
id            = "istmo.data_store"
auto_register = false
```

The registry omits the plugin; you write the `registerHandler` call
yourself.

### Globally

Skip the registry entirely if you want to hand-craft every
registration:

```toml
[app]
auto_register = false
```

`istmo-build` will not emit `IstmoPluginRegistry.{kt,swift}` at all.

## Debugging

If the registry is missing a plugin you expected:

- Confirm the plugin's `istmo.toml` doesn't set `auto_register = false`.
- Confirm you don't have a matching `[[app.plugin]]` override in your
  app.
- Confirm you're not using `role = "client"` for that plugin.

Add a `println!("cargo::warning=…")` in your `build.rs` to inspect the
manifest walked by `collect_dep_manifests()`.
