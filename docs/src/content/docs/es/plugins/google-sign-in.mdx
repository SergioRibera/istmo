`istmo-google-sign-in` envuelve los flows Google Sign-In idiomáticos de
cada plataforma detrás de un solo trait Rust.

- **Android** usa `androidx.credentials` (Credential Manager) más el
  provider `googleid`. Mínimo API 21 (declarado en el `[min_versions]`
  del plugin).
- **iOS** usa el paquete SwiftPM oficial `GoogleSignIn` (7.1+, por el
  parámetro `nonce:`).

No hay backend desktop.

Ambos flows retornan un handle opaco de credencial; el material del
token se queda en el lado nativo y se libera cuando el handle Rust se
dropea.

## Instala

```toml
[dependencies]
istmo-google-sign-in = "0.1.1-alpha.5"
```

Recompila tu app; `istmo_build::emit()` recoge las entradas Gradle +
SwiftPM del plugin automáticamente. El setup de plataforma se limita a
los OAuth clients de abajo.

## Configura los OAuth clients

En la [Google Cloud Console](https://developers.google.com/identity),
dentro de un mismo proyecto, crea:

- Un OAuth client **Web** — su id es `server_client_id`: el
  `serverClientId` en Android y la audience del id token en iOS.
- En Android, un OAuth client **Android** para el package name de la
  app y el SHA-1 del certificado de firma.
- En iOS, un OAuth client **iOS** (ver [Detalles de iOS](#detalles-de-ios)).

El plugin es stateful (`init = SignInConfig`), así que pasas la config
al adquirir el cliente:

```rust
use istmo_google_sign_in::{SignInClient, SignInConfig, SignInMode};

let cfg = SignInConfig::builder("1234-web.apps.googleusercontent.com")
    .scope("email")
    .scope("profile")
    .auto_select(false)
    .build();

let sign_in = SignInClient::from_runtime_with(&runtime, cfg).await?;
// …o sobre el runtime global del proceso: SignInClient::acquire_with(cfg).await?
```

Otros métodos del builder: `.scopes(iter)`, `.hosted_domain(...)` para
tenants de Google Workspace y `.nonce(...)` para protección contra
replay. La salida `Debug` de `SignInConfig`, `SignInAccount` y
`OwnedSignInAccount` oculta el nonce y el id token.

## Inicia sesión

```rust
use istmo_google_sign_in::SignInError;

let account = sign_in
    .sign_in_owned(SignInMode::Interactive)
    .await
    .map_err(SignInError::from)?;

tracing::info!("sesión iniciada como {:?}", account.email);
send_to_server(&account.id_token); // verifícalo en el servidor
// account.credential: NativeHandle<Credential>
```

`SignInMode::Interactive` muestra el selector de cuentas;
`SignInMode::SilentOnly` falla con `SignInError::NoCredentialAvailable`
en lugar de preguntar cuando no hay credencial cacheada.
`silent_sign_in_owned()` retorna `Option<OwnedSignInAccount>` — `None`
en lugar de ese error.

`SignInError::from` decodifica el error propio del plugin a partir del
`IstmoError` del cliente. Los backends no verifican el id token; tu
servidor debe hacerlo.

Usa las variantes `_owned` salvo que necesites reenviar el
`NativeHandleId` crudo — adoptan la credencial en un
`NativeHandle<Credential>` que la libera al dropearse. Los métodos
crudos `sign_in` / `silent_sign_in` / `refresh` retornan
`SignInAccount` con un id suelto; `SignInAccount::into_owned(&runtime)`
lo adopta después.

## Refresca

`refresh` recibe el id de la credencial actual y retorna la cuenta con
un id de credencial nuevo. El id viejo queda consumido: su handle queda
obsoleto (dropearlo es un no-op) y el handle nuevo se libera de forma
independiente:

```rust
let refreshed = sign_in.refresh_owned(account.credential.id()).await?;
drop(account);
```

En iOS el SDK refresca los tokens del usuario autenticado; en Android
Credential Manager no tiene refresh, así que se vuelve a correr el
flow silencioso (falla con `SignInError::Reauthenticate` si no hay
credencial).

## Cierra sesión y revoca

```rust
sign_in.sign_out().await?;
sign_in.revoke().await?;
```

Ambos descartan todas las credenciales que guarda el backend; los
handles que tu código Rust aún posea quedan obsoletos y su liberación
es un no-op. `revoke` además desconecta la app de la cuenta en iOS
(`GIDSignIn.disconnect`). En Android solo limpia el estado local de
credenciales — revoca el permiso desde tu servidor
(`https://oauth2.googleapis.com/revoke`).

## Límites en Android

Credential Manager autentica; no otorga scopes OAuth. Los
`SignInConfig::scopes` extra se ignoran y `granted_scopes` solo lista
`openid`, `email` y `profile`. El inicio silencioso usa auto-select,
así que con exactamente una cuenta autorizada el sistema igual muestra
un breve banner de "iniciando sesión".

## Detalles de Android

El plugin declara sus deps Gradle vía `istmo.toml`:

```toml
[[gradle]]
group    = "androidx.credentials"
artifact = "credentials"
version  = "1.3.0"

[[gradle]]
group    = "androidx.credentials"
artifact = "credentials-play-services-auth"
version  = "1.3.0"

[[gradle]]
scope    = "api"
group    = "com.google.android.libraries.identity.googleid"
artifact = "googleid"
version  = "1.1.1"
```

No hay nada que agregar a tu `build.gradle.kts` — las entradas fluyen
por el handover de native-deps de `istmo-build`.

El flow de Credential Manager necesita una `Activity`. El plugin
declara `android_backend_arg = "activity"`, así que el registry
generado le pasa a `GoogleSignInFactoryImpl` la activity host
(`IstmoGameActivity` lo es).

## Detalles de iOS

El plugin declara el paquete Swift, que el `istmo-plugins.yml`
generado agrega a la app y enlaza en su target:

```toml
[[swift_package]]
url          = "https://github.com/google/GoogleSignIn-iOS.git"
product      = "GoogleSignIn"
from_version = "7.1.0"
```

El backend lee el client id OAuth de iOS de `GIDClientID` en el
`Info.plist` de la app (la convención del propio SDK; sin él el inicio
de sesión falla con `SignInError::InvalidConfiguration`). Defínelo
desde el `istmo.toml` de la app:

```toml
[app.info_plist]
GIDClientID = "1234-ios.apps.googleusercontent.com"
```

El SDK además espera el client id invertido en `CFBundleURLTypes` →
`CFBundleURLSchemes` del `Info.plist`, y que
`application(_:open:options:)` se reenvíe a
`GIDSignIn.sharedInstance.handle(_:)`.

## Cablealo

`SignIn` es stateful (lleva una configuración OAuth por instancia),
así que el `IstmoPluginRegistry` generado lo registra a través del
`GoogleSignInFactoryImpl` del plugin (`android_backend` /
`ios_backend` en su `istmo.toml`). El plugin de Gradle y el fragmento
xcodegen `istmo-plugins.yml` compilan los sources nativos del plugin
dentro de la app, así que no hay nada que copiar.

```kotlin
// IstmoGameActivity, la launcher del template, ya hace esto.
// Una app con su propia activity llama a IstmoHost antes de super.onCreate:
override fun onCreate(savedInstanceState: Bundle?) {
    IstmoHost.onCreate(this) // arranca el runtime + IstmoPluginRegistry
    super.onCreate(savedInstanceState)
}
```

```swift
// ios/<Name>App/main.swift
import IstmoRuntime

IstmoApp.run() // arranca el runtime + IstmoPluginRegistry, luego corre Rust
```

Ver [Auto-registración](/istmo/es/build-scripts/auto-register/) para el
mecanismo completo y los flags de opt-out.

## Backends de referencia

El plugin trae sus backends bajo `plugins/google-sign-in/native/`:

- `android/GoogleSignInBackendImpl.kt` + `GoogleSignInFactoryImpl.kt`
  (paquete `dev.istmo.plugins.googlesignin`, donde `istmo-build`
  también genera el Kotlin del plugin)
- `ios/GoogleSignInBackendImpl.swift` (también define
  `GoogleSignInFactoryImpl`)

Se compilan en cada app que depende del crate. Para personalizar uno,
pon `auto_register = false` para `istmo.google_sign_in` en el
`[[app.plugin]]` de la app y registra tu propio backend.
