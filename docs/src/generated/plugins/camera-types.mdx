### `PixelFormat`

Wire pixel format for streamed frames and still captures.

Prefer the native YUV formats for cheap pass-through; the backend
avoids a colour-conversion pass. [`PixelFormat::Jpeg`] is for
[`Camera::capture_still`] on Android and iOS, which use the hardware
encoder.

| Variant | Payload | Description |
| ------- | ------- | ----------- |
| `Nv21` | — | Android `ImageFormat::NV21` — Y plane + interleaved VU plane. Default on Android. Both mobile backends repack their native 4:2:0 capture into this layout. |
| `Yuv420` | — | Planar / semi-planar 4:2:0. On Android this maps to `YUV_420_888` (three planes); on iOS to `kCVPixelFormatType_420YpCbCr8BiPlanarVideoRange`. |
| `Bgra8` | — | 32-bit BGRA (iOS default when YUV is unavailable). |
| `Rgba8` | — | 32-bit RGBA. |
| `Jpeg` | `u8` | Encoded JPEG. The payload is the hardware encoder's quality knob (`0..=100`); 70 is a typical sweet spot. Still-only on Android and iOS: opening a stream with it reports [`CameraError::FormatUnsupported`]. |

### `CameraError`

Domain-level errors surfaced by every [`Camera`] method.

| Variant | Payload | Description |
| ------- | ------- | ----------- |
| `PermissionDenied` | — | User denied camera access, or the OS declined before the prompt (`AccessStatus::Restricted`). |
| `DeviceNotFound` | `String` | No camera with that id. Devices can disappear between `devices()` and `open()` on hot-plug platforms. |
| `FormatUnsupported` | — | Requested [`PixelFormat`] / resolution / FPS triple is outside what the device advertised. |

| `SessionClosed` | — | Session id does not correspond to a live session (already closed, or the handle was released). |
| `Interrupted` | — | Capture was interrupted by the OS (phone call, resource reclamation on iOS, process restart). Reopen the session. |
