### `AuthPolicy`

Which authenticators may satisfy a request.

Platforms that cannot tell biometric classes apart treat
[`AuthPolicy::BiometricStrong`] and [`AuthPolicy::BiometricWeak`]
alike. Windows Hello always offers its PIN as a fallback, whatever
the policy.

| Variant | Payload | Description |
| ------- | ------- | ----------- |
| `BiometricStrong` | — | Class 3 ("strong") biometrics only — the only class Android accepts for unlocking Keystore keys. |
| `BiometricWeak` | — | Class 2 ("weak") biometrics or better, such as camera-based face unlock on Android devices without dedicated hardware. |
| `BiometricOrDeviceCredential` | — | Strong biometrics, falling back to the device PIN / pattern / password. |

### `BiometricStatus`

Why a device can or cannot satisfy an [`AuthPolicy`].

| Variant | Payload | Description |
| ------- | ------- | ----------- |
| `Available` | — | Authentication can be requested right now. |
| `NoneEnrolled` | — | Hardware is present but the user has not enrolled a biometric (or, for [`AuthPolicy::BiometricOrDeviceCredential`], set up a device credential). |
| `NoHardware` | — | The device has no matching sensor. |
| `HardwareUnavailable` | — | The sensor exists but is temporarily unusable (busy, disabled by policy, disconnected). |
| `LockedOut` | — | Too many failed attempts; biometrics are locked until the user authenticates with the device credential. |
| `SecurityUpdateRequired` | — | Android: a security vulnerability was found and the sensor is disabled until an OS update. |
| `Unsupported` | — | The platform offers no biometric API at all. |

### `AuthPrompt`

Text and behaviour of the system prompt shown by
[`Biometric::authenticate`].

Every platform renders a different subset:

* Android → `title`, `subtitle`, `reason` (as description),
  `cancel_label` (negative button), `confirmation_required`.
* iOS / macOS → `reason` (`localizedReason`), `cancel_label`,
  `fallback_label`.
* Windows → `reason` (dialog message).
* Linux → nothing: fprintd has no UI, so the app must tell the user
  to touch the sensor.

| Field | Wire | Type | Description |
| ----- | ---- | ---- | ----------- |
| `title` | `title` | `String` | Prompt title (Android). |
| `reason` | `reason` | `String` | Why the app asks for authentication. Must not be empty — Apple rejects an empty `localizedReason`. |
| `subtitle` | `subtitle` | `Option<String>` | Secondary line under the title (Android). |
| `cancel_label` | `cancelLabel` | `Option<String>` | Label of the cancel / negative button. Android requires one when the policy excludes the device credential; backends fall back to a localized "Cancel". |
| `fallback_label` | `fallbackLabel` | `Option<String>` | Label of the "enter password" fallback button (Apple). `Some("")` hides the button; `None` keeps the system default. |
| `policy` | `policy` | `AuthPolicy` | Which authenticators may satisfy the request. |
| `confirmation_required` | `confirmationRequired` | `bool` | Android: require an explicit confirmation tap after passive modalities such as face unlock. |
