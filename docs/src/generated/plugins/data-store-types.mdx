### `DataStoreConfig`

Instance-scoped configuration for a [`DataStoreClient`].

The `namespace` is the isolation boundary the native backend uses
to segregate values. Two instances with different namespaces cannot
see each other's keys:

* Android — the `SharedPreferences` file name, used verbatim (so it
  must not contain `/`).
* iOS — the `UserDefaults` suite `<bundle id>.istmo.<namespace>`.
* Desktop — a percent-encoded file name under the app's preference
  directory (see the `desktop` module).

| Field | Wire | Type | Description |
| ----- | ---- | ---- | ----------- |
| `namespace` | `namespace` | `String` | Backend namespace: a short name for one group of values within this app, e.g. `"settings"` or `"session"`. Every platform already keeps one app's storage apart from another's, so there is no need to embed the app id. |

### `DataStoreError`

Domain-level errors returned by every [`DataStore`] method.

| Variant | Payload | Description |
| ------- | ------- | ----------- |
| `Backend` | `String` | Native backend rejected the operation. Carries the platform's error message verbatim (e.g. `SharedPreferences` disk failure, `UserDefaults` suite-locked-out). |
| `Corrupted` | `String` | Stored value could not be decoded into the requested type — usually the sign that a previous version of the app wrote a different shape under the same key. |
