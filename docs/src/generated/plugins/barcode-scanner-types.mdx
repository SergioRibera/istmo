### `BarcodeFormat`

A symbology the scanner may look for.

Not every platform reads every format: iOS has no separate UPC-A
(it reports those as [`Ean13`](Self::Ean13) with a leading `0`) and
reads Codabar only from iOS 15.4. A requested format the platform
cannot read is ignored.

New variants are only ever appended, so existing wire indices stay
stable.

| Variant | Payload | Description |
| ------- | ------- | ----------- |
| `Qr` | — | QR code. |
| `Aztec` | — | Aztec. |
| `DataMatrix` | — | Data Matrix. |
| `Pdf417` | — | PDF417. |
| `Code128` | — | Code 128. |
| `Ean13` | — | EAN-13. |
| `Ean8` | — | EAN-8. |
| `UpcA` | — | UPC-A. |
| `UpcE` | — | UPC-E. |
| `Code39` | — | Code 39. |
| `Code93` | — | Code 93. |
| `Itf` | — | Interleaved 2 of 5 (ITF, including ITF-14). |
| `Codabar` | — | Codabar. |
| `Other` | — | A code the platform read but whose symbology has no variant here. Never matches anything when requested in [`ScanConfig::formats`]. |

### `ScanConfig`

What to scan for.

| Field | Wire | Type | Description |
| ----- | ---- | ---- | ----------- |
| `prompt` | `prompt` | `Option<String>` | Hint shown over the camera where the backend allows one. |
| `formats` | `formats` | `Vec<BarcodeFormat>` | Symbologies to accept. Empty accepts every supported one. |

### `ScannedCode`

A code the scanner read.

| Field | Wire | Type | Description |
| ----- | ---- | ---- | ----------- |
| `text` | `text` | `String` | Decoded text (UTF-8). Empty when the payload is not text — read [`raw`](Self::raw) then. |
| `format` | `format` | `BarcodeFormat` | Symbology of the code. |
| `raw` | `raw` | `Option<Vec<u8>>` | Raw payload bytes, when the platform exposes them. Android always fills it (binary QR codes included); iOS leaves it `None` and skips codes it cannot decode as text. |
