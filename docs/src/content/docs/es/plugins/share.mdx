`istmo-share` abre el menú de compartir de la plataforma con cualquier
combinación de texto, enlace, asunto y archivos, y entrega lo que otras
apps comparten *hacia* la tuya como un stream de `IncomingShare`.

| Plataforma | Enviar | Recibir | Mínimo |
| ---------- | ------ | ------- | ------ |
| Android | chooser `ACTION_SEND(_MULTIPLE)` + `FileProvider` | intent filters `ACTION_SEND` (opt-in) | API 22 |
| iOS | `UIActivityViewController` | Share Extension + App Group | 13.0 |
| macOS | `NSSharingServicePicker` | Share Extension + App Group | 10.15 |
| Windows | `DataTransferManager` | Share Target (sólo MSIX) | 10.0.16299 |
| Linux | — | lo maneja la app | — |

Los mínimos están declarados en el `[min_versions]` del plugin y se
comprueban al compilar (ver la [referencia de istmo.toml](/istmo/es/build-scripts/istmo-toml-reference/#min_versions)).

## Instalación

```toml
[dependencies]
istmo-share = "0.1"
# Opcional: `ShareFile::from_picked` para archivos de istmo-file-picker.
# istmo-share = { version = "0.1", features = ["file-picker"] }
```

## Enviar

```rust
use istmo_share::{ShareClient, ShareError, ShareFile, ShareOutcome, SharePreview, ShareRequest};

let share = ShareClient::from_runtime(&runtime)?;

let request = ShareRequest::text("Fotos del viaje")
    .with_url("https://example.com/viaje")
    .with_subject("Nuestro viaje")
    .with_file(ShareFile::path("/data/user/0/app/files/playa.jpg"))
    .with_file(ShareFile::bytes("itinerario.pdf", pdf_bytes))
    .with_preview(SharePreview {
        title: Some("Nuestro viaje".into()),
        thumbnail: Some(ShareFile::path(thumb_path)),
        fetch_link_metadata: false,
    });

match share.share(request).await.map_err(ShareError::from)? {
    ShareOutcome::Shared(target) => tracing::info!("compartido vía {target:?}"),
    ShareOutcome::TargetChosen(app) => tracing::info!("enviado a {app}"),
    ShareOutcome::Dismissed => {}
    ShareOutcome::Unknown => {}
}
```

`ShareError::from` decodifica el error propio del plugin a partir del
`IstmoError` del client.

### Qué informa cada plataforma

| Plataforma | Eligió destino | Completado | Cancelado |
| ---------- | -------------- | ---------- | --------- |
| Android | `TargetChosen(component)` | no se informa | `Unknown` |
| iOS | — | `Shared(activity type)` | `Dismissed` |
| macOS | `TargetChosen(title)` si el servicio no responde en 60 s | `Shared(título del servicio)` | `Dismissed` |
| Windows 11 | — | `Shared(app user model id)` | `Dismissed` |
| Windows 10 | — | `Shared(app user model id)` | `Unknown` (se resuelve apenas se abre la UI) |

### Archivos

- `ShareFile::path` — un archivo existente. En Android tiene que estar
  dentro de los directorios files o cache de la app; si no, se copia
  antes al cache.
- `ShareFile::bytes` — contenido en memoria; se escribe a un archivo
  temporal con el nombre `name` antes de compartir.
- `ShareFile::from_picked` (feature `file-picker`) — un archivo de
  `istmo-file-picker`: la ruta real si el picker la expone, o el
  contenido si no (SAF en Android).

Los destinos pueden leer los archivos después de que `share` resuelve,
así que las copias temporales se conservan un día en móvil y, en
desktop, hasta que se destruye el `DesktopShare` (o `purge_staged()`).

### Anclaje

En iPad y macOS el menú es un popover. Pasa el rectángulo del botón de
compartir, en puntos de la ventana con origen arriba a la izquierda:

```rust
use istmo_share::{ShareAnchor, ShareRect};

let request = request.with_anchor(ShareAnchor {
    window_id: Some(1), // desktop: id en el registry de istmo-window
    rect: Some(ShareRect { x: 320.0, y: 40.0, width: 44.0, height: 44.0 }),
});
```

Sin anclaje, el menú se centra en la ventana.

### Linux

freedesktop.org no tiene un portal de compartir, así que el backend de
Linux devuelve `ShareError::Unsupported` y `capabilities()` informa
todo en `false`. Renderiza tus propios destinos (copiar al
portapapeles, abrir un `mailto:` con el portal `OpenURI`, …). El
`share_plus` de Flutter hace algo parecido: `mailto:` para texto y sin
soporte de archivos.

```rust
if !share.capabilities().await?.send {
    show_in_app_share_menu();
}
```

## Conectar el backend

El backend necesita una `Activity`, un view controller o una ventana,
así que no se auto-registra.

:::caution[Paquete de Android]
Las fuentes Kotlin del plugin importan los tipos generados desde
`dev.istmo.runtime` (`ShareBackend`, `ShareRequest`, `ShareCodecsImpl`,
…), igual que el resto de los plugins oficiales. Por defecto
`istmo-build` los genera en `<namespace>.gen`, así que la app tiene que
fijar el paquete en su `istmo.toml`; si no, las fuentes del plugin no
compilan:

```toml
[app]
android_package = "dev.istmo.runtime"
```

En iOS no hace falta nada: el Swift generado y las fuentes
`native/ios/` del plugin entran al target de la app a través de
`istmo-plugins.yml`.
:::

**Android** — en `Activity.onCreate`:

```kotlin
val backend = ShareBackendImpl(this)
IstmoRuntime.registerHandler(ShareDispatcher.PLUGIN_ID, ShareDispatcher(backend, ShareCodecsImpl()))
```

El plugin de Gradle mergea el `AndroidManifest.xml` del plugin
(`FileProvider`, receiver del chooser, activity receptora) y
`res/xml/istmo_share_paths.xml` (AGP 8.3+).

**iOS**:

```swift
IstmoRuntime.shared.registerHandler(
    ShareDispatcher.PLUGIN_ID,
    ShareDispatcher(backend: ShareBackendImpl(), codecs: ShareCodecsImpl())
)
```

`istmo-build` agrega `NSPhotoLibraryAddUsageDescription` al
`Info.plist` de la app (lo exige la acción "Guardar imagen").

**Desktop** — registra cada ventana una vez en el registry compartido
de `istmo-window`, desde su hilo de UI:

```rust
use istmo_share::{DesktopShare, ShareClient, ShareHost};
use istmo_window::{WindowId, WindowRegistry};

WindowRegistry::global().register(WindowId(1), &window)?;
let init = Runtime::init(config)?
    .expects::<ShareClient>()
    .host(ShareHost::new(DesktopShare::with_global_registry()?))
    .finish();
```

En Windows el backend hace subclass de la ventana para ejecutar la UI
en su hilo; no bloquees ese hilo mientras esperas `share`.

## Recibir

El contenido compartido llega por `ShareInbox`. Lo que se recibe antes
de que la app se suscriba (arranque en frío desde el menú de
compartir) queda en buffer.

```rust
use istmo_share::ShareInbox;

let inbox = ShareInbox::acquire()?;
let incoming = inbox.stream();
while let Ok(share) = incoming.recv_async().await {
    for file in &share.files {
        import(&file.path, &file.name)?; // copia propiedad de la app
    }
    ShareInbox::cleanup(&share)?;
}
```

Recibir es opt-in en todas las plataformas.

**Android** — agrega al `AndroidManifest.xml` de la app:

```xml
<application>
  <meta-data android:name="dev.istmo.share.RECEIVE" android:value="true" />
  <activity android:name="dev.istmo.plugins.share.ShareReceiverActivity" android:exported="true">
    <intent-filter>
      <action android:name="android.intent.action.SEND" />
      <action android:name="android.intent.action.SEND_MULTIPLE" />
      <category android:name="android.intent.category.DEFAULT" />
      <data android:mimeType="text/*" />
      <data android:mimeType="image/*" />
    </intent-filter>
  </activity>
</application>
```

**iOS / macOS** — agrega un target Share Extension a partir de
`plugins/share/templates/apple-share-extension` (paso a paso en su
`README.md`) y vacía el inbox del App Group: `IstmoShareInbox.drain()`
en iOS, `istmo_share::desktop::drain_app_group_inbox(group, &inbox)` en
macOS.

**Windows** — sólo las apps empaquetadas como MSIX pueden ser destino.
Decláralo en `Package.appxmanifest`:

```xml
<Extensions>
  <uap:Extension Category="windows.shareTarget">
    <uap:ShareTarget Description="Compartir con MiApp">
      <uap:SupportedFileTypes><uap:SupportsAnyFileType /></uap:SupportedFileTypes>
      <uap:DataFormat>Text</uap:DataFormat>
      <uap:DataFormat>URI</uap:DataFormat>
      <uap:DataFormat>StorageItems</uap:DataFormat>
    </uap:ShareTarget>
  </uap:Extension>
</Extensions>
```

Windows lanza una instancia nueva por cada share; al arrancar:

```rust
istmo_share::desktop::take_share_target_activation(&ShareInbox::acquire()?)?;
```

**Linux** — no hay un estándar para ser destino. Pasa los archivos de
tu handler `MimeType` del `.desktop` o de la línea de comandos al mismo
stream con `ShareInbox::publish`.
