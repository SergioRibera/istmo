`istmo-live-activity` mapea ActivityKit de iOS 16+ y notifications
persistentes de Android detrás de un trait Rust. Describes los
atributos y estado de tu activity en Rust; ambas plataformas renderizan
idiomáticamente.

## Instala

```toml
[dependencies]
istmo-live-activity = "0.1.1-alpha.5"
```

## Modela tu activity

Los atributos son inmutables por activity; el estado se actualiza
sobre su lifetime.

```rust
use istmo_live_activity::{
    ActivityStyle, DismissalPolicy, TypedLiveActivity,
};

#[istmo::message]
pub struct TimerAttributes {
    pub title:          String,
    pub target_seconds: u32,
}

#[istmo::message]
pub struct TimerState {
    pub elapsed_seconds: u32,
    pub label:           String,
}
```

`TypedLiveActivity<A, C>` fija los tipos de atributos y estado en
compile-time y los encodea con wincode antes de cruzar el wire. El
`LiveActivityClient` subyacente es stateless — bindealo una vez por
tipo de activity:

```rust
let activities =
    TypedLiveActivity::<TimerAttributes, TimerState>::new(&runtime, "timer")?;

let handle = activities.start(
    TimerAttributes { title: "Focus block".into(), target_seconds: 25 * 60 },
    TimerState { elapsed_seconds: 0, label: "0:00 / 25:00".into() },
    ActivityStyle::Standard,
).await?;
```

## Update

```rust
activities.update(
    handle.id(),
    TimerState { elapsed_seconds: 60, label: "24:00 remaining".into() },
    None, // AlertConfig opcional
).await?;
```

`handle` es un `NativeHandle<LiveActivityToken>`. Dropearlo *no*
termina la activity — llamá `end()` explícitamente. Si querés que una
activity sobreviva muerte del proceso, persistí `handle.id()` y
re-adoptalo tras el restart via `activities.restore()` (retorna las
activities vivas filtradas por activity-type).

## End

```rust
activities.end(
    handle.id(),
    Some(TimerState { elapsed_seconds: 25 * 60, label: "Done".into() }),
    DismissalPolicy::Default,
).await?;
```

El estado final renderiza brevemente antes de que la activity sea
removida. `DismissalPolicy::Immediate` salta el render;
`AfterSeconds(n)` lo mantiene `n` segundos.

## Detalles de iOS

- Las Live Activities necesitan iOS 16.2+ (`ActivityKit`). El plugin
  compila también para versiones anteriores, donde `capabilities()`
  reporta `activity_kit_available: false`.
- Tu `Info.plist` necesita `NSSupportsLiveActivities = YES`.
- **Debes** implementar un struct `ActivityAttributes` Swift
  matcheado con la misma forma que tus `Attributes`/`State` en Rust.
  El `TimerLiveActivityHandler.swift` de referencia en el repo del
  plugin muestra el patrón.
- La extensión Widget (SwiftUI) renderiza los layouts compacto +
  expandido. El plugin no genera el código SwiftUI — lo escribes una
  vez y se queda quieto.

## Detalles de Android

- Requiere API 26+ (`NotificationChannel`), declarado en el
  `[min_versions]` del plugin.
- Renderiza como una notification persistente con custom content
  view.
- Usa `NotificationChannel` con `IMPORTANCE_LOW` por default; ajusta
  en tu copia de `NotificationLiveActivityHandler.kt`.
- Las notifications sobreviven muerte de proceso; adopta de vuelta
  con el id persistido.

## Cablealo

El `IstmoPluginRegistry` generado construye `LiveActivityDispatcher` con
el `LiveActivityBackendImpl` del plugin (compilado dentro de la app
desde `plugins/live-activity/native/`); los entry points del runtime
lo llaman al startup.

```kotlin
// IstmoGameActivity, la launcher del template, ya hace esto.
// Una app con su propia activity llama a IstmoHost antes de super.onCreate:
override fun onCreate(savedInstanceState: Bundle?) {
    IstmoHost.onCreate(this) // arranca el runtime + IstmoPluginRegistry
    super.onCreate(savedInstanceState)
}
```

```swift
// ios/<Name>App/main.swift
import IstmoRuntime

IstmoApp.run() // arranca el runtime + IstmoPluginRegistry, luego corre Rust
```

Ver [Auto-registración](/istmo/es/build-scripts/auto-register/) para el
mecanismo completo.

## Handlers de referencia

El repo del plugin envía dos estrategias de renderizado bajo
`plugins/live-activity/native/`:

- **iOS `ActivityKitLiveActivityHandler`** — invoca ActivityKit.
- **Android `NotificationLiveActivityHandler`** — renderiza como
  notification persistente con una RemoteView inflada.

Ambos están pensados para ser **copiados y customizados** — renderizan
layouts específicos por app. El resto del plugin (protocolo, dispatch,
codec) nunca cambia.
