El auto-wiring del lado Rust recoge los **clients** de plugins
transparentemente vía `istmo::runtime!` (ver
[Auto-wiring](/istmo/es/advanced/auto-wiring/)). El lado nativo necesita su
propio mecanismo porque los **backends** de plugin —
`<T>BackendImpl.kt` / `<T>BackendImpl.swift` — son código del usuario
que sólo la app sabe cómo construir.

`istmo-build` cierra el gap emitiendo un archivo
**`IstmoPluginRegistry`** dentro de tu app. Llamás `registerAll(...)`
una vez y cada dispatcher elegible se cablea al runtime.

## El archivo generado

Para una app cuyo package Android resuelve a `com.myapp.gen`,
`istmo-build` escribe:

```kotlin
// android/app/src/main/java/com/myapp/gen/IstmoPluginRegistry.kt
// GENERATED by istmo-build - DO NOT EDIT.

package com.myapp.gen

import android.content.Context
import dev.istmo.runtime.IstmoRuntime

object IstmoPluginRegistry {
    fun registerAll(context: Context, runtime: IstmoRuntime = IstmoRuntime.instance) {
        runtime.registerHandler(
            DataStoreDispatcher.PLUGIN_ID,
            DataStoreDispatcher(
                DataStoreFactoryImpl(context),
                DataStoreCodecsImpl(),
            ),
        )
        // …un bloque por cada plugin auto-registerable
    }
}
```

El espejo iOS vive en
`ios/<AppDir>/Plugins/IstmoPluginRegistry.swift` con un
`enum IstmoPluginRegistry.registerAll(...)` correspondiente.

## Invocarlo

Cablea el registry en tu `Activity.onCreate` (Android) o `App.init`
(iOS) al lado del startup del runtime:

```kotlin
// Android
override fun onCreate(savedInstanceState: Bundle?) {
    IstmoRuntime.instance.start(this)
    IstmoPluginRegistry.registerAll(applicationContext)
    super.onCreate(savedInstanceState)
}
```

```swift
// iOS
@main
struct MyApp: App {
    init() {
        IstmoRuntime.shared.start()
        IstmoPluginRegistry.registerAll()
    }
    var body: some Scene { ... }
}
```

Ese es todo el wire-up. Sin llamadas `registerHandler` por plugin.

## Qué significa "elegible"

Un plugin aparece en el registry cuando se cumplen **todos**:

- El role del plugin es `host` (el lado nativo implementa el backend).
  Plugins con role `client` no registran un dispatcher — generan un
  `<T>Client` para que el lado nativo llame.
- El `istmo.toml` del plugin tiene `auto_register = true` (default).
- El `istmo.toml` de la app no override con `auto_register = false`
  para ese plugin.
- El `[app] auto_register` app-level no es `false`.

Todo lo demás cae a registración manual.

## Convención de construcción

El registry construye el dispatcher asumiendo una convención fija:

- **Plugins stateless**: `<T>Dispatcher(<T>BackendImpl(...), <T>CodecsImpl())`.
- **Plugins stateful** (trait declarado con `init = Config`):
  `<T>Dispatcher(<T>FactoryImpl(...), <T>CodecsImpl())` — el factory
  materializa un backend por instancia.

Argumento pasado al constructor del backend/factory:

- **Android**: `context: Context` (el `applicationContext` que pasaste
  a `registerAll`).
- **iOS**: sin argumentos — constructores Swift que necesitan config
  extra alcanzan `IstmoRuntime.shared` o singletons app-level.

Si tu `BackendImpl`/`FactoryImpl` de plugin necesita algo más,
opt-out y registrá manualmente.

## Opt-out

### Por plugin (autor del plugin)

Declará el plugin como no-auto-registerable en su propio `istmo.toml`:

```toml
[plugin]
id            = "acme.push_notifications"
client_type   = "::acme_push::PushClient"
auto_register = false
```

Esta es la opción correcta cuando el backend tiene un constructor
bespoke que varía entre apps (ej. requiere una API key al construir,
o un `HttpClient` compartido).

### Por plugin (autor de la app)

Override en el `istmo.toml` de la app:

```toml
[[app.plugin]]
id            = "istmo.data_store"
auto_register = false
```

El registry omite el plugin; escribís la llamada `registerHandler` a
mano.

### Globalmente

Skip el registry entero si querés hand-craft cada registración:

```toml
[app]
auto_register = false
```

`istmo-build` no va a emitir `IstmoPluginRegistry.{kt,swift}` en
absoluto.

## Debugging

Si el registry no incluye un plugin que esperabas:

- Confirmá que el `istmo.toml` del plugin no seta `auto_register = false`.
- Confirmá que no tenés un `[[app.plugin]]` matcheado con override en
  tu app.
- Confirmá que no estás usando `role = "client"` para ese plugin.

Agregá un `println!("cargo::warning=…")` en tu `build.rs` para
inspeccionar el manifest que camina `collect_dep_manifests()`.
